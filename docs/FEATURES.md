# Ples ERP — возможности и статус реализации

Документ нужен, чтобы портфолио было убедительным, но не вводило читателя в заблуждение. Состояние отражает контрольные документы и историю разработки; оно не заменяет новую сквозную проверку всей системы.

## Web Frontend и Backend

| Область | Описание | Статус по проектной документации |
|---|---|---|
| Авторизация и роли | Проверка пользователя, роли и доступа к магазину | Реализовано; требует стандартной проверки в целевом окружении |
| Номенклатура | Каталог и поиск товаров | Реализовано |
| Поступления | Журнал поступлений и работа с позициями | Реализовано в веб-системе; детали зависят от текущей сборки |
| Продажи и возвраты | Серверная бизнес-логика и хранение истории операций | Реализовано |
| Статистика | Агрегированные данные по продажам и возвратам | Реализовано |
| Изоляция магазинов | Отдельная SQLite-база магазина и серверные проверки доступа | Предусмотрено архитектурой; требует регулярных проверок безопасности |
| Резервное копирование | Полноценный безопасный процесс резервного копирования и восстановления | Отдельный этап развития |

## Android Cashier

| Возможность | Статус по контрольной точке |
|---|---|
| Локальная продажа через Outbox | Реализовано |
| Локальный возврат через Outbox | Реализовано |
| Многотоварная продажа и возврат | Реализовано |
| Возврат по штрихкоду | Реализовано |
| Идентификатор операции и идемпотентность | Реализовано |
| Фоновая синхронизация через WorkManager | Реализовано |
| ACK и статусы синхронизации | Реализовано |
| Миграция старой локальной SQLite-базы | Реализовано |
| Диагностика синхронизации | Реализовано |
| Полный эксплуатационный цикл в демонстрационном облачном окружении | Не заявляется до отдельной проверки |

В контрольной точке проекта записаны успешные результаты тестовой синхронизации SALE и RETURN с ACK. Это подтверждает проверку соответствующих сценариев в разработческой среде, но не является гарантией работы любой будущей конфигурации.

## Что следует проверить перед публичным показом

1. Запустить актуальный Backend и Frontend из согласованных веток.
2. Проверить вход, каталог, поступление, продажу и возврат.
3. Проверить Android Cashier: продажу без сети, восстановление сети и подтверждение синхронизации.
4. Проверить Android Administrator: поступления, историю продаж и статистику.
5. Убедиться, что демонстрация не использует реальные данные магазина.
6. Убедиться, что демонстрационная SQLite находится отдельно от рабочих баз и может быть восстановлена из тестового набора.
7. Проверить, что конфигурация, секреты и административные учётные записи не попали в публичный репозиторий.

## Ограничения

Ples ERP создавалась прежде всего для собственного магазина. Она не должна представляться как полностью готовая, сертифицированная или универсальная коммерческая платформа. Возможности, совместимость и готовность к эксплуатации в чужом бизнесе необходимо подтверждать отдельным тестированием и настройкой.

Статус «реализовано» означает наличие функциональности по контрольной документации; перед записью публичного видео её нужно повторно проверить на актуальной сборке.
