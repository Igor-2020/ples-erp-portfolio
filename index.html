Ples ERP — практическая система, выросшая из реальных задач небольшого интернет-магазина. Веб-интерфейс, серверная бизнес-логика и отдельные Android-приложения работают как части одного проекта.

Единая система

Три рабочих слоя. Одна предметная область.

Компоненты разделены по ответственности, чтобы веб-интерфейс и мобильные приложения могли использовать общую серверную логику.

⌘

Web Frontend

Страницы веб-системы для работы с каталогом, поступлениями и другими операциями магазина.

HTML · CSS · JavaScript
⇄

Backend API

Серверная бизнес-логика, авторизация, контроль доступа и работа с данными SQLite.

Java 21 · Spring Boot
▣

Android

Отдельные приложения кассира и администратора. Кассовый клиент спроектирован для работы offline-first.

Kotlin · Room · WorkManager
Ключевой принцип
«Сначала надёжная операция. Потом синхронизация».
✓

Локальная касса.
Продажа и возврат могут быть сохранены на устройстве без немедленного доступа к серверу.

✓

Очередь операций.
Outbox и фоновая задача управляют отправкой, повторами и состояниями обработки.

✓

Подтверждение сервера.
Приложение учитывает ACK и не приравнивает наличие интернета к завершённой синхронизации.

Возможности и честный статус

Создаётся для реальной работы

Основные сценарии реализованы по контрольной документации проекта. Отдельные функции и эксплуатационные этапы ещё требуют завершения и проверки.

Учёт и операции Реализовано

Номенклатура, поступления, продажи, возвраты, история операций и статистика присутствуют в проекте. Перед внешним внедрением нужна проверка на конкретной конфигурации.

Offline-first касса Реализовано

Локальные операции, Outbox, фоновая синхронизация и ACK зафиксированы в контрольной точке Android Cashier.

Администратор Android В развитии

Основные экраны поступлений, номенклатуры, продаж, возвратов, статистики и просмотра сотрудников описаны как реализованные.

Печать и эксплуатация В работе

Физическая печать этикеток ещё не реализована полностью. Резервное копирование, публичный demo-стенд и финальная стабилизация требуют отдельной работы.

Мой вклад
От задачи магазина — к системе из нескольких приложений.
01

Постановка задач.
Выявление практических потребностей магазина и выбор последовательности реализации.

02

Проектные решения.
Согласование структуры компонентов, API, офлайн-сценариев и требований к поведению системы.

Разработка с ИИ-инструментами.
Использование ИИ как помощника при создании и изменении кода — без заявления о ручном написании каждой строки.

Интеграция и проверка.
Сборка компонентов, тестирование сценариев и фиксация известных ограничений перед следующим этапом.
